# LNF — правила конфига

LNF — фреймворк виджетов для рабочего стола (wlr-layer-shell). Панель
описывается **обычным Go-кодом** в `panel.go` (функция `panelConfig`), а движок
(`main.go`, `wl.go`) рисует слои прямо в разделяемую память компоновщика.
Никакого GL и никакого cgo — чистый Go.

Композиторы: sway/swayfx, niri и Hyprland — всё, что умеет `wlr-layer-shell`.
Системные действия идут через `wm.sh`, индикатор воркспейсов — через `ws.sh`,
скриншот — через `shot.sh`; каждый сам выбирает бэкенд (`swaymsg`, `niri`,
`hyprctl`), так что конфиг от композитора не зависит.

Логика остаётся в shell: команды опросов (`Poll.Command`) и действий
(`ClickExec`, `MenuCmd` и т.п.). Конфиг — это только данные: где что стоит,
какого цвета и что запускается по клику.

```sh
cd ~/LNF
go build -trimpath -ldflags="-s -w" -o lnf .   # пересобрать
./lnf                                           # запустить
pkill -x lnf                                    # остановить (не pkill -f!)
```

Правка панели = правим `panel.go`, пересобираем, перезапускаем. Отдельного
«языка конфига» больше нет — его роль играют структуры `Config` и `Layer`.

---

## 1. Как устроена панель

`panelConfig()` возвращает список сцен `[]*Config`. **Каждая сцена — это
отдельная поверхность слоя** со своим фоном, якорем, размером и шрифтом, но все
они живут в одном процессе и одном соединении с компоновщиком. Обычно сцена одна.

Сцена содержит список слоёв `[]*Layer` — кнопок, надписей, фигур. Порядок
слоёв в списке = порядок отрисовки: кто **позже**, тот рисуется **поверх**.
Поэтому фон панели добавляется первым.

В `panel.go` есть готовые помощники:

```go
newConfig("m3")   // сцена с значениями по умолчанию; имя → namespace "lnf-m3"
newLayer("clock") // слой с значениями по умолчанию
col("#8FD98F")    // цвет из строки (#rgb / #rrggbb / #rrggbbaa / none)
shape("M -1 -1 L 1 -1 L 1 1 L -1 1 Z") // контур из команд M/L/C/Z
ms(300)           // 300 миллисекунд в секундах (для Appear)
```

Дальше просто заполняем поля.

Сейчас панель — это «печенька»: один плавающий виджет в правом нижнем углу с
отступами от краёв (сцена `cookie`). Корпус — контур печеньки из семи круглых
бугорков, он берётся готовым SVG-путём (`cookieOutline`) и нормируется в
`cookiePath`; по нижней дуге корпуса стоят блокировка, сон, выход и включение —
всё на одном круге. Клик в любой точке печеньки (корпус, тарелка, время, дата,
ресурсы) раскрывает веер действий, карточки буфера/скриншота/
обоев живут в сцене `pop` слева от виджета, панель приложений — у левого края
в сцене `apps`. Пример ниже — учебный: непрозрачная
капсула справа сверху; её поверхность размером с раскрытый ящик, а видимая
часть мала:

```go
cfg := newConfig("m3")
cfg.W, cfg.H = 300, 720                 // высота — под самый большой ящик
cfg.Anchor = anchorRight | anchorTop
cfg.Margin = [4]int32{14, 14, 0, 0}

add := func(l *Layer) { cfg.Layers = append(cfg.Layers, l) }

bar := newLayer("bar")                  // сама капсула
bar.Radius, bar.FG = 30, col("#1B211BFF")
bar.Anchor, bar.HasAnchor = anchorLeft|anchorRight|anchorTop, true
bar.H = 60
add(bar)
```

Прозрачная площадь вокруг капсулы мышь не ловит — область ввода сужается до
видимых слоёв (см. §11), так что капсула не мешает окнам под ней.

**Место под капсулу.** Чтобы окна не заходили под панель, вторая сцена резервирует
полосу сверху (`exclusive zone`). Важно: у поверхности, прижатой к углу
(`top+right`, как капсула), положительная зона компоновщиком обнуляется — поэтому
резервирует отдельная невидимая полоса во всю ширину, прижатая к `top+left+right`:

```go
res := newConfig("res")                 // пустая сцена: только место, без слоёв
res.Anchor = anchorTop | anchorLeft | anchorRight
res.W, res.H = 0, 74                    // W=0 — растянуть во всю ширину
res.Exclusive = 74                      // столько занято капсулой (14 + 60)
```

Опечатку в имени поля поймает компилятор (`go build`) — это и есть главный
выигрыш от конфига на Go.

## 2. Сцена — `Config`

| поле | смысл | по умолчанию |
|---|---|---|
| `Title` | заголовок окна (в Wayland сейчас не используется) | `"LNF"` |
| `W`, `H` | размер в пикселях; `0` = тянуться между якорями | `200`, `40` |
| `BG` | фон поверхности; нулевой цвет = «дыры» наружу | прозрачный |
| `Layer` | `background`, `bottom`, `top`, `overlay` | `"top"` |
| `Anchor` | биты `anchorTop/anchorBottom/anchorLeft/anchorRight` | `anchorTop\|anchorLeft` |
| `Margin` | `[4]int32{top, right, bottom, left}` — отступ поверхности от края экрана | нули |
| `Namespace` | имя поверхности, видно в `niri msg layers` | `"lnf"` / `"lnf-<имя>"` |
| `Exclusive` | сколько пикселей зарезервировать у края; `-1` = не резервировать | `-1` |
| `FontPath` | путь к `.ttf`/`.otf` | первый системный шрифт |
| `FontSize` | размер шрифта по умолчанию для слоёв | `14` |
| `GroupsOn` | имена групп, раскрытых сразу при старте (см. §3) | пусто |
| `Polls` | список опросов (см. §6) | пусто |
| `Layers` | список слоёв (см. §3) | пусто |

Раскладку поверхности отдаём компоновщику: `anchor top,left,right` + `H = 36`
даёт полосу сверху во всю ширину; `anchor right,top,bottom` + `W = 300`, `H = 0`
даёт панель во всю высоту справа.

## 3. Слой — `Layer`

**Геометрия.**

* `X`, `Y`, `W`, `H` — позиция и размер в пикселях (используются, только если нет якоря);
* `Anchor` (`uint32`) + `HasAnchor` (`bool`) — раскладка по краям поверхности:
  `left+right` растягивает по ширине, `top+bottom` — по высоте, один якорь
  прижимает к краю, без якорей — по центру;
* `Margin` `[4]float64{top, right, bottom, left}` — отступы от краёв поверхности;
* `DX`, `DY` — сдвиг поверх якорной раскладки (ряд кнопок сессии сдвигается по `DX`).

**Вид.**

* `Cmds` — форма из §7 (если пусто, рисуется только текст);
* `Radius` — если задан (в пикселях) и `Cmds` пусто, вместо формы рисуется
  скруглённый прямоугольник: `Radius` = половине меньшей стороны даёт капсулу
  или круг. Проще и надёжнее форм, когда нужна именно капсула/пилюля;
* `FG` — цвет заливки фигуры (по умолчанию белый);
* `Style` — принимается, но поддержана только заливка (`"fill"`);
* `StrokeW` — ширина обводки, принимается, но не используется;
* `Text` — текст на слое (рисуется по центру слоя по вертикали);
* `TextAlign` — `"left"`, `"center"`, `"right"`;
* `TextFG` + `HasTextFG` — цвет текста (иначе как `FG`);
* `TextPad` — внутренний отступ текста от краёв (по умолчанию `4`);
* `FontSize` — свой размер шрифта у слоя.

**Отклик на мышь.**

* `HoverFG` + `HasHover` — цвет формы под курсором;
* `TextHover` + `HasTextHi` — цвет текста под курсором;
* `HoverScale` — множитель размера под курсором (`1.12` — рост на 12 %);
* `HoverShift [2]float64` — сдвиг под курсором `{x, y}`, пиксели;
* `HoverRot` — дополнительный наклон под курсором, градусы;
* `Rotate` — постоянный наклон, градусы (текст тоже поворачивается).

Слой становится «живым» (ловит курсор и события), только если у него задан хотя
бы один отклик: `Hover*`, `ClickScale > 0`, любое `*Exec`, `SpinDur > 0`,
`Toggle` или `MenuCmd`. Слой с одним лишь `Text` кликов не ловит — удобно для
часов и показаний.

**Анимация.**

* `Appear` — плавное появление при старте, секунды (пишите `ms(300)`); заодно
  форма подрастает с 85 % до 100 %;
* `AppearDX`, `AppearDY` — при появлении слой выезжает из этого сдвига (в
  пикселях) в своё место: `AppearDY = -30` даёт выезд сверху вниз, «из-под
  капсулы», как полка из ящика;
* `ClickScale` — насколько сжаться при нажатии (`0.18` — на 18 %);
* `ClickDecay` — жёсткость пружины нажатия, больше = резче (по умолчанию `9`);
* `SpinDur` — крутить после клика столько секунд;
* `SpinDelay` — но начать через столько;
* `SpinTurns` — сколько оборотов за это время (по умолчанию `6`). Обороты целые,
  поэтому к концу вращения слой встаёт ровно в исходную ориентацию.

Появление и пружины досчитываются в такт кадров и только пока что-то
анимируется: когда всё улеглось, процесс спит. Вечно «дышащей» анимации нет.

**Действия** (все идут через `sh -c`, можно пайпы и подстановки):

| поле | когда |
|---|---|
| `ClickExec` | левая кнопка |
| `RightExec` | правая кнопка |
| `MiddleExec` | средняя кнопка |
| `WheelUp` / `WheelDown` | колесо вверх / вниз |

**Раскрывашки.** Слой с `ShowWhen = "имя"` виден, только когда включена группа
`имя` (по умолчанию выключена). Слой с `Toggle = "имя"` переключает эту группу по
левому клику. Группы **взаимоисключающие**: открытие одной закрывает прочие, так
что в один момент раскрыт один ящик. Когда при открытии перечитываются меню
(`MenuCmd`), список всегда свежий — на этом держится буфер обмена.

Ящик не появляется и не исчезает рывком: `appearT` едет к цели (1 при открытии,
0 при закрытии), а `Appear`/`AppearDX`/`AppearDY` задают, из какого сдвига он
выезжает. Поэтому закрытие — это та же анимация наоборот (ящик уезжает назад и
растворяется).

Так сделан виджет: кнопки веера — `Toggle = "apps"` / `"clip"` / `"shot"` /
`"walls"`, а карточки — слои с `ShowWhen` тех же групп; корпус и подписи
тоже `Toggle = "fan"`. Клик по пункту меню (`MenuCmd`)
выполняет команду и закрывает свой ящик; ПКМ — вторичное действие (см. §3 меню).

**Меню-список.** У слоя задан `MenuCmd` — LNF один раз выполняет команду и
рисует вывод строками. Формат строки:

```
подпись <TAB> команда <TAB> значок <TAB> цвет <TAB> ПКМ-команда
```

Всё, кроме подписи, необязательно. Если «значок» начинается с `/` — это путь
к PNG, и рисуется **настоящая иконка** (её отдаёт `drun.sh`). Иначе «значок» —
глиф шрифта: при непустом «цвете» он рисуется белым в цветной скруглённой
плитке, без цвета — просто знаком перед подписью. Пятое поле — «вторичное»
действие: по **ПКМ** по строке выполняется эта команда, а список перечитывается
(ящик остаётся открытым) — так удаляется запись буфера обмена. Высота пункта —
`RowH` (по умолчанию `40`), внутренний отступ — `Pad`. Наведение подсвечивает
пункт цветом `FG`, подпись — `TextFG` / `TextHover`; клик левой кнопкой
выполняет команду пункта и закрывает ящик, колесо прокручивает список.

**Слежение.** `Follow` — имя другого слоя; этот слой ползёт за курсором внутри
того слоя. `Axis` — `"x"` (по умолчанию) или `"y"`. `Pad` — отступ, ближе
которого к краю чужого слоя он не заходит. Внутри области слежения движение
сглажено, за её пределами упирается в край.

## 4. Значения

* **число** — `34`, `0.5`, `-0.21`: размеры/координаты в пикселях, масштабы —
  множитель, `Rotate` — градусы.
* **цвет** — через `col(...)`: `#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa`, `#` и
  слова `none`/`transparent` для полной прозрачности. Байт альфы — прозрачность
  поверх обоев; размытия нет.
* **длительность** — в секундах, поэтому есть помощник `ms(...)`.
* **якорь** — биты: `anchorTop`, `anchorBottom`, `anchorLeft`, `anchorRight`.
* **контур** — через `shape(...)`, синтаксис в §7.
* **текст** — обычная Go-строка; шаблоны и подстановки в §8. Значки шрифта
  пишутся прямо: `"\uf011"`.

## 5. Песочница и повторение

Раз это Go — повторяющиеся виджеты делаются циклом, а не копипастой. Так
собираются кнопки сессии в `panel.go`:

```go
sessions := []struct {
	name, glyph, cmd string
	danger           bool
}{ /* ... */ }
for i, s := range sessions {
	l := newLayer(s.name)
	l.Radius, l.FG = 17, powerBg // круг из скруглённого прямоугольника
	l.ClickExec = s.cmd
	cx, cy := polar(219+float64(i)*34, 66) // дуга по низу печеньки
	put(l, cx, cy, 34, 34)
	add(l)
}
```

## 6. Опросы — `Poll`

```go
cfg.Polls = []*Poll{
	{Name: "load", Command: `awk '{printf "LA %.2f", $1}' /proc/loadavg`, Interval: 5 * time.Second},
}
```

Команда запускается через `sh -c`, её stdout обрезается по краям и становится
значением опроса. Цикл: выполнить сразу при старте → пауза `Interval` → снова.
Ошибка запуска игнорируется: если команда молчит, старое значение остаётся.

Значения опросов **глобальны на процесс**: одна и та же команда не запустится
дважды, даже если её объявили в двух сценах. Имя опроса используется в тексте
как `{имя}`.

Каждый опрос — отдельный процесс на каждый тик. Не ставьте `Interval` в сотни
миллисекунд для тяжёлых команд. Панель при этом перерисовывается **только когда
значение реально изменилось** — частый лёгкий опрос кадры не гонит.

**Берегите простой.** Каждый опрос — это `fork` круглосуточно, а на ноутбуке это
прямо батарея. Раз в секунду — разумный предел; для событийных вещей (громкость,
уведомления) опрос вообще не нужен — шлите значение через `lnf.sh set`. Часы
`{time:…}` тоже не требуют секундного тика: движок сам будит цикл ровно к смене
минуты.

Пример — индикатор воркспейсов niri (`ws.sh` печатает по значку на воркспейс:
`●` активный, `○` остальные):

```go
cfg.Polls = []*Poll{{Name: "ws", Command: "$HOME/LNF/scripts/workspace_status.sh", Interval: time.Second}}

ws := newLayer("ws")
ws.Text, ws.TextFG, ws.HasTextFG = "{poll:ws}", onVar, true
ws.TextAlign, ws.TextPad = "left", 106
ws.Anchor, ws.HasAnchor = anchorLeft|anchorTop, true
ws.H = 60
ws.FontSize = 17
```

## 7. Формы

`shape(...)` — путь в духе SVG из команд:

```
M x y            — начать контур в точке
L x y            — линия в точку
C x1 y1 x2 y2 x y — кубическая кривая: две контрольные точки и конец
Z                — замкнуть контур
```

Координаты нормированы в квадрат от −1 до 1 относительно прямоугольника слоя:
−1 — левый/верхний край, 1 — правый/нижний, 0 — центр. Форма заполняет слой
целиком, а `W`/`H` задают пропорции. Можно несколько подконтуров (несколько `M`),
но надёжнее один замкнутый контур.

Нормировка по осям означает, что у широкой низкой капсулы одна и та же форма
даст разные радиусы по горизонтали и вертикали. Поэтому для капсул, ящиков и
круглых кнопок удобнее `Radius` (§3) — он задаётся в пикселях и не зависит от
пропорций. `shape(...)` остаётся для произвольных контуров.

## 8. Текст и подстановки

Внутри `{...}` работают:

* `{имя}` — текущее значение опроса `Poll.Name = "имя"` (пусто, если опроса нет);
* `{poll:имя}` — то же, длинная форма;
* `{time:...}` — текущее время; формат как в `strftime`: `%H` часы, `%M` минуты,
  `%S` секунды, `%I` 12-часовой час, `%p` AM/PM, `%d` день, `%e` он же с пробелом,
  `%m` месяц, `%b`/`%B` месяц словом, `%a`/`%A` день недели, `%Y`/`%y` год,
  `%j` день года, `%Z` зона, `%%` процент. Примеры: `{time:%H:%M}`, `{time:%a %d %b}`.

Если в тексте есть `{time:...}`, процесс будится раз в секунду, чтобы часы
успевали меняться; без них — только по факту изменения опросов.

Условной раскраски нет: от состояния может зависеть текст (команда опроса вернёт
`тихо` вместо `100%`), а цвет — нет. Всё, что похоже на логику, делает команда.

## 9. Приложения: полноэкранный лаунчер (drun)

Приложения открываются кнопкой-лаунчером в капсуле (`Toggle = "apps"`), а сам
список живёт на **отдельной полноэкранной overlay-поверхности** — сцене `apps`.
Вид — как Launchpad в macOS, но в духе Material 3: рабочий стол темнеет
(скрим-слой), сверху по центру «пилюля» поиска, ниже — центрированная сетка
плиток «значок + подпись».

```go
apps.Layer, apps.Keyboard = "overlay", 1  // overlay + клавиатура для поиска
grid.MenuCmd   = "$HOME/LNF/scripts/app_launcher.sh"
grid.Grid      = true                     // режим сетки (вместо списка строк)
grid.Cols      = 8                        // максимум столбцов
grid.CellW, grid.CellH = 150, 132         // CellW — плотность, CellH — высота
grid.IconSize  = 64                       // сторона значка
grid.EmptyText = "Ничего не найдено"      // что показать, когда фильтр пуст
```

Сетка: `Cols` ограничивает число столбцов сверху, `CellW` задаёт плотность
(столбцов ровно столько, сколько помещается), блок центрируется по горизонтали.
Наведение рисует «слой состояния» цветом `FG` под ячейкой, колесо прокручивает
по строкам, клик запускает приложение и закрывает группу. Без указания `CellW`
сетка просто растягивает `Cols` на всю ширину.

`drun.sh` читает `.desktop`-файлы из системных каталогов, выкидывает служебные
коды (`%U`, `%f`, …) и собирает строки `подпись <TAB> команда <TAB> значок <TAB> цвет`.
Значок — **настоящая иконка приложения**: скрипт находит PNG по имени `Icon=`
(беря самый крупный размер), а если есть только SVG — растеризует его через
`rsvg-convert` (или `magick`) в кэш `~/.cache/lnf-icons`. Если иконки нет вовсе,
подставляется глиф шрифта и цвет плитки (тогда значок рисуется в цветном квадрате).
Чтобы добавить своё соответствие «глиф/цвет» — допишите строку в `drun.sh`.

Кнопка-лаунчер — это слой с `Toggle`, а список — слой с `ShowWhen`:

```go
launcher.Toggle = "apps"    // по клику раскрывает/сворачивает группу
menu.ShowWhen   = "apps"    // виден только когда группа раскрыта
cfg.GroupsOn    = []string{"apps"} // раскрыт сразу при старте
```

Кнопки сессии и питания на виджете постоянные (без `ShowWhen`): они лежат по
нижней дуге корпуса и работают до раскрытия веера.

## 9a. Буфер обмена (cliphist)

История буфера — тоже пункт меню, просто другая команда:

```go
clip.MenuCmd = "$HOME/LNF/scripts/clipboard_history.sh"
clip.ShowWhen = "clip"
```

`clip.sh` берёт последние записи `cliphist list`: первой строкой — «Очистить
всё» (`cliphist wipe`), дальше записи `подпись <TAB> команда <TAB> значок <TAB>
цвет <TAB> ПКМ`. Левая кнопка кладёт запись в буфер (`cliphist decode ID |
wl-copy`), правая — удаляет только её (`cliphist delete ID`) и обновляет список.
Вставить потом — обычным Ctrl+V; автоматической вставки нет. Список
перечитывается при каждом раскрытии ящика, так что всегда свежий.

Слежение за буфером обеспечивает сам `cliphist` — держите запущенными вотчеры
(обычно в автозапуске компоновщика):

```sh
wl-paste --type text  --watch cliphist store &
wl-paste --type image --watch cliphist store &
```

## 9b. Утилиты и обои (`scripts/utils_wallpaper.sh`, `scripts/set_wallpaper.sh`)

Ящик «утилиты» — тоже `MenuCmd`, но список собирает `utils.sh`:

```go
utils.MenuCmd = "$HOME/LNF/scripts/utils_wallpaper.sh"
utils.ShowWhen = "utils"
```

Сверху — обои из каталога (`$LNF_WALLS` или первый из `~/Изображения`,
`~/Pictures/Wallpapers`, `~/Pictures`, …). Для каждой картинки `utils.sh` делает
миниатюру через `magick` в `~/.cache/lnf-walls` и отдаёт её как «значок» —
поэтому в списке видны сами обои, а не имена файлов. Ниже — полезности:
остановить обои, приглушить звук, скриншот, блокировка, перезапуск LNF.

Постановка обоев — своя программа: `lnf wallpaper` / `lnf wallpaperd`
(`wallpaperd.go`), без awww, swaybg и swww.

* демон — клиент `zwlr_layer_shell_v1` на слое `background`, рисует в `wl_shm`
  (ARGB8888), по поверхности на каждый `wl_output`;
* декодирует сам PNG, JPEG и WebP, масштаб — cover (центр по центру, без
  искажений); при `scale = 2` рисует в физических пикселях и сообщает
  компоновщику `set_buffer_scale` — без мыла на HiDPI;
* переход — плавное смешение за 300 мс (`fade <мс>` через FIFO), без
  аллокации кадра на каждый тик;
* подключённый на ходу монитор сразу получает текущие обои;
* `lnf wallpaper gen:sage|moss|dew` — генерирует градиент без файлов;
* управление — FIFO `$XDG_RUNTIME_DIR/lnf-wallpaper.fifo`:
  `set <путь|gen:имя>`, `fade <мс>`, `quit`.

В простое демон держит около 15 МБ: один shm-буфер из двух, второй отдаётся
ядру через `madvise` и поднимается только на время перехода. CPU в простое —
ноль (цикл спит в `poll`).

Скрипт `set_wallpaper.sh` — тонкая обёртка над этим, панель зовёт его же.

## 9c. Всплывающий OSD (громкость)

Слой умеет «вспыхивать» по изменению опроса — так сделан OSD громкости. У слоя
задаются `Flash = "имя_опроса"` и `FlashFor` — сколько его держать:

```go
obg := newLayer("osd-bg")
obg.Flash, obg.FlashFor = "vol", 1400*time.Millisecond
obg.Appear, obg.AppearDY = ms(200), 16 // выезжает и уплывает анимацией
```

Как только значение опроса `vol` меняется, все слои с `Flash = "vol"` появляются
(`appearT` 0→1), держатся `FlashFor` и плавно прячутся (1→0). Первый замер при
старте изменением не считается — при запуске OSD не всплывает. `osd.sh` печатает
`значок ██░░ 45%`, а OSD-сцена в `panel.go` центрируется на экране (без якорей).

**Громкость приходит событием, а не опросом.** Держать опрос `wpctl` круглосуточно
(да ещё дважды в секунду) — зря жечь батарею. Вместо этого клавиши `XF86Audio*` в
niri зовут `vol.sh`: он меняет громкость и разово шлёт панели новое значение:

```sh
# keybinds.kdl
XF86AudioRaiseVolume { spawn-sh "~/LNF/scripts/volume_control.sh up"; }
# vol.sh делает wpctl + `lnf.sh set vol "$(osd.sh)"`
```

Команда `set ИМЯ ЗНАЧЕНИЕ` обновляет опрос и взводит вспышку — OSD показывается
мгновенно и ровно один раз, без фонового опроса. Так же можно слать любое
внешнее значение (`lnf.sh set <имя> <значение>`).

Тем же механизмом сделан **OSD сообщений** — сцена `msg` (баннер сверху по центру):
`Flash = "notify"`; текст берётся из подстановки `{poll:notify}`, куда пишет
`lnf.sh notify «текст»`.

## 9d. Управление извне — `lnf.sh`

Панель читает команды из FIFO (`~/.cache/lnf/lnf.fifo`), который создаёт при
старте. `lnf.sh` пишет туда строку — так кейбинды niri дёргают ящики и OSD:

```sh
lnf.sh fan             # раскрыть/свернуть веер действий
lnf.sh apps            # открыть/закрыть «Приложения» (с поиском)
lnf.sh clip            # буфер обмена
lnf.sh shot            # скриншот: задержка и зона
lnf.sh walls           # обои
lnf.sh toggle NAME     # любая группа
lnf.sh set NAME VALUE  # задать значение опроса (OSD без опроса)
lnf.sh notify «текст»  # баннер сообщения
```

Одна группа за раз: открытие закрывает прочие. FIFO дешёвый — опросов не добавляет.

Клик по кнопке-раскрывашке переключает группу **во всех сценах, где она есть**
(`Scene.OnGroup` → `backend.group`), а не только на своей поверхности: иначе ящик,
живущий на другой поверхности (лаунчер приложений — на своей overlay-сцене), не
открывался бы кликом.

Для скриптов и тестов есть `lnf.sh type ТЕКСТ` (вписать текст в открытый поиск)
и `lnf.sh key backspace|enter|escape`.

## 9e. Поиск в приложениях

Слой-меню с `Search = true` фильтруется строкой поиска сцены; строка показывается
слоем с текстом `{poll:search}`. Ввод идёт по `wl_keyboard`: панель сама читает
раскладку из `wl_keyboard.keymap` и переводит скан-коды в буквы (латиница и
кириллица) — `zwp_text_input_v3` не используется, потому что без IME в niri он
текст не отдаёт. Escape/Backspace/Enter ловятся по коду клавиши напрямую. Пока
открыт лаунчер, overlay-поверхность просит клавиатуру эксклюзивно
(`Keyboard = 1` у сцены `apps` → `keyboard_interactivity = exclusive (1)`), при
закрытии отпускает (`none (0)`). Enter запускает первый подходящий пункт, Escape
закрывает. Заодно это чинило поиск: капсула на слое `top` фокус брала ненадёжно,
а overlay-поверхность — стабильно.

## 10. Отладка

```
LNF_DEBUG=1 ./lnf             # сводка по сценам
LNF_STATS=1 ./lnf             # раз в секунду: кадры, что анимируется, память
LNF_DUMP=/tmp/o.png ./lnf     # не показывать, а отрендерить в PNG и выйти
LNF_TRACE=1 ./lnf             # трассировка протокола Wayland
LNF_MOUSE=40,44 ./lnf         # притвориться, что курсор в этой точке
LNF_SPIN=1.5 ./lnf            # включить вращение кнопки через 1.5 с (проверка)
LNF_GROUPS=power ./lnf        # раскрыть группы (для дампа)
LNF_SEARCH=disc LNF_GROUPS=apps ./lnf   # ящик приложений со строкой поиска
LNF_NOTIFY=текст ./lnf        # баннер сообщения
LNF_KEYS=1 ./lnf              # трассировка клавиатуры/раскладки в stderr
LNF_MEM_LIMIT=256 ./lnf       # мягкий лимит heap в МБ (по умолчанию 256)
```

Быстро проверить кадр, не глядя на экран: `go test -bench . -benchtime 100x` —
бенчмарки в `bench_test.go` меряют отрисовку панели, лаунчера и синтетического
«жирного» конфига на 300 слоёв.

Дамп рисует каждую сцену в отдельный файл (`o.png`, `o-2.png`, …) — видно
результат, не глядя на экран. Живые поверхности видны в `niri msg layers` по
`Namespace`.

## 11. Что виджет умеет вообще

Поверхность слоя рисуется прямо в разделяемую память компоновщика, без GL и EGL:
шрифт и заливка форм считаются на процессоре, с альфой. Отсюда следствия: фон
может быть прозрачным, но размытия под ним нет. Область ввода поверхности LNF
сужает до видимых слоёв (`wl_surface.set_input_region`), поэтому прозрачные
участки мышь **не** перехватывают: маленькая капсула на большой прозрачной
поверхности не мешает кликам по окнам под ней, а выезжающие ящики — ловят.

Управление системой — это не отдельная функция, а следствие того, что опросы и
действия запускают команды: открыть приложение, убить процесс, переключить звук,
перезапустить службу, прочитать что угодно в текст. Чего пока нет: чтения
долгоживущего процесса построчно (события вместо интервала), отдельных
всплывающих поверхностей (попап — это выезжающий слой внутри своей поверхности,
см. `ShowWhen`/`Toggle` и `MenuCmd`) и условной раскраски по состоянию.

Сборка: `GOARCH=386 go build -trimpath -ldflags "-s -w" -o lnf .` — 32-битная не
потому, что нужны 32 бита, а потому, что у 64-битного Go фиксированные ~1.2 ГБ
виртуального адресного пространства; у 386-сборки — ~9 МБ. Реально занятая
память в обоих случаях около 8 МБ.
